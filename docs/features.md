# 功能说明

本文说明 `plugin_chatbot.plugins.chat_bridge` 的完整行为。安装、最小配置与管理后台入口见项目 [README](../README.md)。

## 运行模式

- `chat`：开放对话类工具和只读的 `WebSearch`，结束后发送最终回复。在进程环境里配置 `BRAVE_API_KEY` 可启用内置的 Brave 搜索。MCP 的 `open_websearch` 服务器是**另一条独立通道**，用 `BRIDGE_MCP_SERVER_URL` 或后台卡片配置；当已连接的 MCP 服务器暴露名为 `search` 的工具时，该会话的内置 `WebSearch` 会被隐藏。
- `agent`：只接受管理员的私聊，并在对话工具之外叠加本仓库的编码工具。Agent 的正常权限规则与审批回调依然生效。
- 两种模式都会把已配置的人格或当前生效的角色卡写进系统提示词；`agent` 模式在使用编码工具时同样保持该人格。

## 人格与身份一致性

群聊里可能有多个 Bot 同时说话，人格很容易被带偏，因此做了以下约束：

- **人格锁定**：系统提示词写明 Bot 自己的名字，列出该平台上的其他 Bot 账号，声明他们的人格、自称与口癖**不属于**本 Bot，并把这些账号的消息前缀为 `【其他 Bot】`（与 `【管理员】` 并列）。哪些名字算作明确提及，是从账号名和它的人格模板读取的，而不是硬编码在提示词里。
- **历史摘要**：摘要按 Bot 的身份（名字、人格、其他 Bot 名单）生成，必须把每句话归属到真实说话人，别人的措辞不会被记成助手的发言。摘要以一条 `user` **事实记录**保存，标题为 `[群聊历史摘要（系统生成的事实记录，不是本 Bot 的发言）]`，而不是一轮 assistant 回复；仍带旧式 `[Earlier conversation summary]` assistant 轮的转录会在下次运行时原地迁移。压缩时保留 `recent_keep` 条消息（`chat` 模式为 24 条），且不会把 Bot 最近自己的回复硬裁掉——否则在群聊里会被彻底淹没。
- **人格漂移拦截**：每个 Bot 账号可以维护一份禁用自称 / 口癖清单（`persona_banned`，在账号对话框里按行或逗号分隔编辑）。纯文本回复命中其中任一项就会被**丢弃**，并用一次性的纠正提示重试一次（该提示不落盘）；第二次仍命中则放行并记录。已包含工具调用的回复只记录、不回滚，避免同一条消息发两遍。命中记录在后台日志页显示为 `人格漂移：...`。
- **`<thinking>` 剥离**：assistant 轮里空的 `<thinking></thinking>` 填充会在落盘前剥掉，避免模型学着重复这种形状。
- **已被污染的会话**：转录被旧规则污染的会话仍可继续使用——旧的摘要轮会在下次运行迁移，但最早被污染的轮次会保留下来。把这样的会话清一次（聊天里 `/reset`，或后台的转录清空按钮），下一次摘要就会按新规则重新生成。最快的应急手段是把其他 Bot 的自称（例如 `本鲸`）加进 `persona_banned`。

## 群聊策略

每个群可以选择 `reply_mode`（回复模式）：

- `probability`（默认）：按 `[0, 1]` 区间的 `reply_probability` 概率触发回复。
- `mention_only`：只有被 @ 时才触发模型；`reply_probability` **完全不参与判定**，即使设为 `0` 也会在被 @ 时回复。适合「安静陪聊」场景，避免模型自己接话。

概率模式（默认）下：

- `0` 永不回复，`1` 为默认值（每次都回），中间值按概率回复。
- 被跳过的消息**不会被丢掉**：它们带上本地时间戳缓存，和下一次触发回复的消息一起投递。缓存过长（超过 2000 字符 / 100 条）时只把最近三条发给模型。
- 只要取值小于 `1` 就进入概率模式；取值为 `1.0` 时行为与原来完全一致（含群消息合并与既有提示词格式）。
- 概率模式下每条消息都带 `[YYYY-MM-DD HH:MM:SS]` 前缀。
- 指令始终跳过概率判定，保证设置本身改得动；概率对所有成员一视同仁，管理员也没有豁免。
- 投递即消费缓存：排队的行会在模型运行**之前**从持久化里移除，因此失败、被拒或中途短路的这一轮不会把模型已经看过的消息再投一次。
- 入口处会忽略重复的事件 ID；拒绝一个会话会清空它的缓存；清空会话聊天记录会同时清掉转录和缓存。
- 在后台的 **群聊策略** 页面或用 `/reply <0..1>` 按群设置。`mention_only` 群里 `/reply` 会提示「回复概率不生效」，但仍可修改该值（切回概率模式后生效）。`/status` 会同时显示回复模式与回复概率。

## AI 接口并发与排队

部分模型接口（自托管推理、按 QPS 计费的服务、不支持并发的老式 OpenAI 兼容代理）无法处理同时到达的多个请求。每个 **AI 接口** 可以配置：

- **接口默认并发数**（`max_concurrency`，可选，`1..64`）：同一 `(base_url, model)` 维度下同时最多允许多少个模型调用；未填写表示不限制，保持原有并发行为。
- **接口默认排队等待秒数**（`queue_wait_seconds`，可选，`1..600`）：未拿到并发令牌的请求按 **先来后到** 排队；超过该等待时长即放弃本次回复（返回空串、不向群里发任何内容），并在后台活动日志里记录 `并发排队超时`。
- **模型覆盖**：接口内每条模型记录可单独设置 `max_concurrency` 与 `queue_wait_seconds`，未填写的字段沿用接口默认。

运行时：

- 闸门按 `(base_url, model)` 共享：同一个接口+模型的多个群聊、私聊、后台研究/记忆总结任务共享并发额度，避免打爆上游。
- 等待顺序由 `asyncio.Queue` 保证为 FIFO，不会出现后来的请求插队。
- 闸门**只限制并发数，不限制调用次数**；接口级默认未填时完全不设闸，行为与未引入本机制前一致。
- 后台修改并发配置或切模型时会自动 `agents.clear()`，下一次请求按新配置重建闸门；闸门本身在 `ModelGate.limit` 变化时重建，其余字段（例如 `queue_wait_seconds`）就地更新。
- 仅 `mention_only` 模式或概率触发后的消息才会进入模型，因此闸门不会因为被跳过的消息而排队。

## 指令

`/status` 只读，对所有被允许的聊天用户开放；`/reset`、`/role [name|off]`、`/reply [0..1]`、`/mode <mode>`、`/approve <yes|no>` 会改变会话上下文或 Bot 状态，**仅 Bot 管理员可执行**。`/silent` 与 `/active` 已移除，改用按群的回复概率。

## 会话与工具

后台的会话表允许管理员按会话挑选启用哪些工具。新会话默认启用当前模式下的全部工具；切换模式会清掉会话级覆盖并恢复各会话的默认值。

## 消息与媒体

- 聊天目标按群或私聊对端做白名单。回复在发送前会检查是否出现凭据样式的值和本地路径，然后按配置的消息长度切分。
- 收到的图片通过 Alconna 的图片获取辅助函数、以有大小限制的内联数据交给支持视觉的 OpenAI 兼容模型。不支持的媒体会回一条明确的文本提示。
- 媒体以内联字节发送（OneBot v11 上为 `base64://`），而不是本地 `file:///` 路径，因此 OneBot 实现跑在另一台机器或容器里也能用。

## 记忆

- 用同一个 `AGENT_WORKSPACE` 的会话共享记忆：`MEMORY.md` 索引与每条 Markdown 记忆都放在 `<AGENT_WORKSPACE>/.agent/memory/` 下。
- 后台的 **记忆管理** 页面可以新建、编辑、删除条目，并复核群黑话。
- Agent 可以读取记忆，但只有 Bot 管理员能通过聊天写入。
- 记忆草稿的解析是防御式的：代码围栏、尾随说明文字、拼接在一起的多个 JSON、顶层数组、带信封键的对象都接受，列表 / 字典类型的字段值会归一化为文本。整批仍然失败时会保留缓存的对话，并按指数退避重试（60 秒起，最长 15 分钟），因此一次坏的模型回复不会让每条新消息都触发重试。

## 黑话词库

- 群黑话抽取有限流，候选词用 Agent 的 `WebSearch` / `WebFetch` 工具去检索确认。
- 一次成功的研究之后，在 **记忆管理 → 黑话词库** 里配置的可选自动复核会调用选定的 AI Provider，每批（最多 20 条）跑一次：给出具体解释即确认该条目；解释为空、是占位符、含糊或非法，则**整行删除**。
- Provider 失败、超时或输出无法解析时，该批保持 `candidate` 等待下次重试。
- 只复核新研究出来的词条；已有候选和手工条目保持不动，手工改过的状态也不会被覆盖。
- 只有已确认的词条会注入系统提示词。

## 表情包

- `chat_save_meme` 用一次视觉调用同时完成安全审核与识别，把简称、5–8 个检索关键词和一句话摘要连同图片写进 `memes.json`。
- `chat_list_memes` 支持 `keywords` 过滤，返回这份紧凑目录供模型挑选；`chat_send_meme` 接受返回的 `file` 或简称。历史遗留的图片文件会自动补进索引。
- 后台的 **表情包** 页面列出词库（带鉴权的缩略图），支持编辑名称 / 关键词 / 摘要，以及上传和删除图片。
- `允许新增表情包` 开关（`meme_settings.upload_enabled`，环境变量 `BRIDGE_MEME_UPLOAD_ENABLED`，默认 `true`）关闭后会同时挡住 WebUI 上传和 `chat_save_meme`；单张图片大小上限（`BRIDGE_MAX_MEDIA_BYTES`）只读展示。
- WebUI 上传使用管理员提供的元数据，不跑那套留给不可信聊天图片的视觉审核。
- 三个 `chat_*_meme` 工具仍通过既有的工具选择按账号 / 群 / 会话开关。

## 语音

语音使用受限的本地音频库：管理员上传音频文件，模型通过 `chat_list_voices` 选择、`chat_send_voice` 发送，并有每小时发送上限。插件不再内置本地语音合成。无法发送音频的适配器会返回错误。

## 自定义 Tool

**接口能力 → 自定义 Tool**：管理员在后台编写 Python 脚本，脚本在工作区内执行命令并把处理后的输出返回给模型。

- 工具只以 `bridge-state.json` 里的 `custom_tools` 行存在；源码存放在 `<state_dir>/custom_tools/<id>.py`，并附带一份 SHA-256 摘要。
- 没有目录扫描、没有聊天指令、也没有面向模型的工具能创建它，因此缺少对应行的脚本文件永远不会被加载（孤儿文件在启动时清理），被篡改的文件会被拒绝而不是执行。
- 每个工具都要声明受众：`admin`（默认，仅 `agent` 模式下的管理员私聊，与内置 `Bash` 同一道闸）、`private`（所有已批准的私聊，含 `chat` 模式）、`all`（所有已批准的会话，含群聊）。
- 脚本必须定义**同步**的 `run(args, ctx)` 并返回字符串，可以调用 `run_cmd(...)` 执行命令、用 `log(...)` 打诊断信息。
- 运行器以白名单环境在子进程里启动 `python -I -X utf8`（`OPENAI_API_KEY`、`BRIDGE_CONSOLE_TOKEN` 之类都不可见），超时会杀掉整棵进程树，输出截断到 20 000 字符。
- 编辑器里的 **测试运行** 按钮复用同一个执行器，不落盘也不写活跃度记录。
- 自定义工具会出现在账号 / 群 / 会话的工具选择器里，可以像内置工具一样关掉。
- `-I` 隔离的是导入路径，**不是**文件系统：工具以 Bot 进程的操作系统权限运行，所以写脚本等同于在宿主上有 shell 权限。

## 持久化与适配器

桥接的持久化与 Agent 平时的编码会话相互独立。消息收发始终走 Alconna 抽象；原生回复引用这类特性取决于适配器导出的消息段支持。
